# Design — ML Foresight

> Brouillon initial du projet, avant le pivot v1.1.0.
> Pour les détails finaux voir [`../rapport.md`](../rapport.md).

## Problème

Foresight émet des signaux 0-100 via formule heuristique. Winrate 46-48 % à T+24h, sous le hasard. → remplacer par du ML supervisé.

**Tâche** : classification binaire `direction_correct` (le marché a-t-il bougé dans le bon sens à T+24h ?).

## Architecture

3 repos GitHub dans l'org `foresight-ml-poc` :

- `ml-foresight` — pipeline ML, structure calquée sur basile-desjuzeur/ml-poc-project
- `backend-foresight` — FastAPI qui charge le best model + scaler depuis GitHub Release
- `frontend-foresight` — React + Vite, démo qui appelle le backend

Contrat partagé : `models/model_card.json` qui définit `feature_order`, `model_version`, et les métriques. Backend et frontend pilotent dessus.

## Données

Source : DB Postgres de Foresight, tables :

- `signals` : id, direction, market_price_at_signal, source_tier_mix (JSONB), cosine_score, signal_score, created_at
- `signal_outcomes` : direction_correct (cassé pour 408/438 lignes — calcul manuel depuis move_t24h_pct), price_t24h, move_t24h_pct
- `event_market_analysis` : impact_strength, llm_confidence, ambiguity_score, specificity_score
- `events` : bucket, articles_count, unique_sources_count

Label calculé en SQL :

```sql
CASE
  WHEN s.direction IN ('BUY_YES', 'YES', 'UP') THEN (so.move_t24h_pct > 0)::int
  WHEN s.direction IN ('BUY_NO',  'NO',  'DOWN') THEN (so.move_t24h_pct < 0)::int
  ELSE NULL
END AS direction_correct
```

Sortie : ~411 signaux du 2026-04-12 au 2026-05-04, 216 losses / 195 wins.

## Pipeline

1. `scripts/export_from_foresight.py` : SQL → `data/raw/signals_export_<date>.csv`
2. `scripts/train.py` : load + clean + feature engineer + train 3 modèles (LogReg, RF, GBM) + sauve `.joblib` + génère plots
3. `scripts/main.py` (fixé Basile) : load les `.joblib` + évalue sur test set + lance Streamlit

## Features (~17 après one-hot)

- 4 LLM : impact_strength, llm_confidence, ambiguity_score, specificity_score
- 5 signal-time : cosine_score, is_buy_yes (depuis direction), market_price_centered, hour_of_day, tier_1/2/3_count (depuis JSONB source_tier_mix)
- 2 event-context : articles_count, unique_sources_count
- one-hot bucket

## Modèles

- LogisticRegression — baseline linéaire, GridSearchCV sur C
- RandomForestClassifier — bagging, RandomizedSearchCV
- GradientBoostingClassifier — boosting séquentiel (substitut au MLP Keras qui hangait sur cet env)

Sélection : meilleure ROC-AUC sur test set.

## Heuristique baseline

Plutôt que de re-implémenter la formule (et devoir matcher les inputs), on utilise directement la colonne `signals.signal_score` (déjà calculée par Foresight à l'émission). Seuil binaire > 65 → label 1.

## Anti-leak

`EXCLUDED_FROM_FEATURES` dans `src/config.py` :
- Future-derived : `move_t24h_pct`, `outcome_label`, `price_t24h`, `price_resolved`
- Heuristic outputs : `signal_score`, `signal_strength`, `trade_quality`

Scaler fit sur train only. Tuning hyperparamètres via 5-fold CV sur train, jamais sur le test.
